Understanding Scale in Earth Engine

Scale determines the size of pixels used in computations and exports. If you do not set it, Earth Engine guesses from your map zoom-leading to inconsistent results. Always be explicit.

Learning objectives

  • Define spatial, temporal, and radiometric resolution.
  • Find a dataset's native resolution.
  • Set scale in reducers and exports to avoid surprises.
  • Troubleshoot "too many pixels" errors with scale choices.

Why it matters

Scale controls accuracy, runtime, and cost. A missing scale can change your statistics when you zoom the map or cause tasks to fail.

Three kinds of resolution

  • Spatial: pixel size (Landsat 30 m, Sentinel-2 10-60 m, MODIS 250-1000 m).
  • Temporal: revisit time (Landsat 16 days, Sentinel-2 5-10 days, Planet daily).
  • Radiometric: bit depth (8-bit: 0-255; 16-bit: 0-65,535).

Always set scale

// reduceRegion: specify scale
var stats = image.reduceRegion({
  reducer: ee.Reducer.mean(),
  geometry: roi,
  scale: 30  // match Landsat native resolution
});

// Export: specify scale
Export.image.toDrive({
  image: image,
  description: 'export_example',
  region: roi,
  scale: 30
});

Pro tips

  • Use native resolution when possible; coarsen (larger scale) for large regions to avoid timeouts.
  • Print image.projection() and image.projection().nominalScale() to confirm native scale.
  • Set maxPixels and bestEffort only when you understand the trade-offs.

Try it: inspect native scale

var l8 = ee.Image('LANDSAT/LC08/C02/T1_L2/LC08_044034_20210623');
print('Projection', l8.projection());
print('Native scale (m)', l8.projection().nominalScale());

Compare with Sentinel-2 and MODIS to see different scales.

Common mistakes

  • Letting zoom level dictate scale (results change when you pan/zoom).
  • Using a finer scale than native and expecting new detail (upsampling adds no new information).
  • Ignoring projection differences when mixing datasets-reproject or use resample carefully.

Handling "too many pixels"

var stats = image.reduceRegion({
  reducer: ee.Reducer.mean(),
  geometry: largeArea,
  scale: 100,      // coarser to reduce pixels
  maxPixels: 1e9,
  bestEffort: true
});

Coarsen scale first; raising maxPixels is secondary.

Quick self-check

  1. Where do you set scale for a reducer?
  2. What does nominalScale() return?
  3. Why does upsampling not add detail?

Next steps

  • Run the same reducer at 10 m, 30 m, and 100 m; compare runtime and results.
  • Practice reprojecting one dataset to match another before combining them.
  • Apply explicit scale in exports for reproducible outputs.
