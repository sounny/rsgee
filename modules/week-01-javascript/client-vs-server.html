Client vs Server Objects

Understanding the Two Worlds

When you write code in the Earth Engine Code Editor, you're actually working with two different environments:

  • Client-side (Browser): Your web browser running JavaScript
  • Server-side (Google Cloud): Google's powerful computers that do the heavy lifting

This distinction is fundamental to understanding how Earth Engine works and avoiding common errors.

Client-Side Objects

Client-side objects are regular JavaScript objects that exist in your browser. They include:

  • Regular numbers: var x = 5;
  • Regular strings: var name = 'Landsat';
  • Regular arrays: var list = [1, 2, 3];
  • JavaScript Date objects: var today = new Date();

These objects are processed by your browser and cannot be used directly in Earth Engine computations.

Server-Side Objects (ee.Objects)

Server-side objects are Earth Engine objects that represent data and computations on Google's servers. They always start with ee.:

  • Earth Engine numbers: var x = ee.Number(5);
  • Earth Engine strings: var name = ee.String('Landsat');
  • Earth Engine lists: var list = ee.List([1, 2, 3]);
  • Earth Engine dates: var today = ee.Date(Date.now());

These objects are processed on Google's servers, which have access to petabytes of satellite imagery and massive computing power.

The Key Rule

⚠️ Important: Do NOT mix client-side and server-side objects. Use ee. functions with ee. objects.

❌ This Will Break:

// Mixing client and server - DON'T DO THIS
var serverNumber = ee.Number(5);
var result = serverNumber + 10;  // ERROR! Can't add client number to server number
print(result);

✅ This Works:

// Using server methods correctly
var serverNumber = ee.Number(5);
var result = serverNumber.add(10);  // Using ee.Number.add() method
print(result);  // Prints: 15

Why Does This Matter?

Understanding client vs server is essential because:

  1. Debugging: Many errors come from mixing client/server objects
  2. Performance: Server-side operations are parallelized across Google's infrastructure
  3. Scale: You can process global datasets that would never fit in your browser's memory

Common Mistakes to Avoid

Mistake Solution
serverNum + clientNum serverNum.add(clientNum)
Using JavaScript for loops with collections Use .map() instead
Using getInfo() (blocks browser) Use evaluate() for async operations

Key Takeaways

  • Objects starting with ee. live on Google's servers
  • Use ee. methods (like .add(), .subtract()) instead of JavaScript operators
  • The print() function sends objects to the server and retrieves results asynchronously
  • When in doubt, wrap your data with an ee. constructor
